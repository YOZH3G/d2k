# D2K — Dynamic2Keenetic

D2K наблюдает трафик на Keenetic, измеряет подозрительные соединения, создаёт обход и запоминает рабочее решение. C-runtime, без Zapret/nfqws. TLS 1.2, TLS 1.3, QUIC и Telegram-туннель входят в тестовый MVP.

## Установка / обновление — одна команда

Выполняйте **в SSH-терминале Entware на роутере от root**, не на компьютере и не в командной строке KeeneticOS. Архитектуру установщик определяет автоматически по Entware и `uname` — см. [совместимость](#архитектуры) и [подготовку](#перед-первой-установкой).

```sh
(f=$(mktemp) && curl -fsSL --connect-timeout 10 --max-time 120 https://raw.githubusercontent.com/necronicle/d2k/feat/telegram-tunnel/scripts/install.sh -o "$f" && D2K_REF=feat/telegram-tunnel sh "$f"; r=$?; rm -f "$f"; exit "$r")
```

Сейчас устанавливается ветка **`feat/telegram-tunnel`**, не `main`: это публичная тестовая сборка, не стабильный релиз. Скрипт запускается только после полной успешной загрузки. Перед выполнением можно [посмотреть его код](scripts/install.sh).

## Полное удаление — одна команда

```sh
(f=$(mktemp) && curl -fsSL --connect-timeout 10 --max-time 120 https://raw.githubusercontent.com/necronicle/d2k/feat/telegram-tunnel/scripts/uninstall.sh -o "$f" && sh "$f"; r=$?; rm -f "$f"; exit "$r")
```

Удаляются службы, панель, правила D2K, его Instagram DNS-записи, конфигурация, найденные обходы и ключ Telegram. **Изученное состояние будет потеряно.** Чужие правила и DNS-записи не удаляются. [Код удаления](scripts/uninstall.sh).

## Перед первой установкой

1. Установите Entware и включите компонент Keenetic **«Модули ядра подсистемы Netfilter»**. [Официальная инструкция Entware](https://support.keenetic.com/hero-5g/kn-4110/en/20980-installing-the-entware-repository-on-a-usb-drive.html) приведена для ARM64-модели; на сайте выберите свою модель.
2. Подключитесь к **Entware по SSH**, используя его адрес, порт и пароль root. Архитектуру можно посмотреть командами `uname -m` и `opkg print-architecture`.
3. Один раз подготовьте зависимости:

   ```sh
   opkg update && opkg install curl ca-bundle iptables ipset kmod_ndms xtables-addons_legacy openssl-util
   ```

   Команды `ip` и `start-stop-daemon` также должны быть доступны в Entware. Установщик проверяет их, NFQUEUE и connbytes до изменения работающей установки.
4. Остановите z2k, Zapret и другие сервисы, вмешивающиеся в тот же трафик. Затем выполните команду установки выше. Для загрузки нужен доступ к GitHub; при ошибке загрузки скрипт не продолжит установку неполного комплекта.

## После установки

- D2K запускается автоматически в активном режиме (`MODE=apply`) и подбирает обходы по живому трафику. Начального списка заблокированных сайтов нет; первый поиск может потребовать времени.
- Семейства доменов изучаются автоматически по собственным подтверждённым обходам. После объединения новое совместимое имя сразу получает обход семейства, без отдельного поиска или записи каждого поддомена. TLS 1.2, TLS 1.3, QUIC, ECH и IPv4/IPv6 не смешиваются; реально отличающийся узел может получить своё точечное решение. [Проверка на роутере](docs/field/2026-10-01-learned-domain-families.md).
- Панель доступна **на роутере**: `http://<LAN-адрес-роутера>:8090/`, обычно **http://192.168.1.1:8090/**. Точный адрес напечатает установщик. Никаких команд на компьютере или SSH-туннелей для панели не требуется.
- В панели работают кнопки управления движком и Telegram. У неё **нет пароля**: доступ доверен локальной сети. Не публикуйте порт 8090 в интернете.
- Telegram включается автоматически: роутер создаёт собственный ключ и регистрируется на relay по HTTPS. Вводить общий секрет не нужно; приватный ключ не покидает роутер. Туннель перенаправляет только Telegram TCP, не весь интернет.
- DNS Instagram и WhatsApp Web: роутер получает свежие адреса от собственного C-резолвера d2k на VPS (`https://213.176.74.63.nip.io:9443/resolve`), проверяет диапазоны Meta, доступность узла и его сертификат, затем сохраняет свои записи на роутере (1–2 адреса на имя). Имена: `instagram.com`, `www.`/`graph.`/`api.`/`i.instagram.com`, `instagram.c10r.instagram.com`, `static.`/`scontent.cdninstagram.com`, `static.`/`scontent.xx.fbcdn.net`, `web.`/`www.`/`graph.`/`v.whatsapp.com`, `scontent.`/`static.`/`mmg.`/`pps.whatsapp.net`. Имена точек присутствия CDN заранее не прописываются — это работа обхода. Блокировка имени не считается неисправностью IP: обход SNI подбирает движок отдельно. Первое обновление идёт в фоне сразу после установки (установка его не ждёт; обновление версии не повторяет его, если последнее удалось меньше суток назад), далее — ежедневно в окне **01:00–04:59 по времени роутера** со своей для каждой установки минутой; при неудаче повтор через 30 минут, 1 час, 2 часа… но не позже следующего дня; прежние записи сохраняются. Семейства Instagram, WhatsApp и fbcdn закрепляются независимо (Instagram — только при проверенном `instagram.com`). Каждая своя запись ежедневно проверяется с самого роутера; недоступная снимается, и имя снова решается обычным DNS — даже если VPS недоступен (если не отвечает ни одна запись, это считается сбоем связи роутера, и записи не трогаются). Конфигурация NDM сохраняется только при изменении записей.
- Повторная команда установки обновляет файлы, сохраняя конфигурацию, найденные обходы и ключ Telegram. Ручное отключение туннеля тоже сохраняется.

## Управление и диагностика

### Исправления перехвата 30.09.2026

Измерения не захватывают DNS на портах 53/853 и локальный resolver IPC.
Направления NFQUEUE ограничены conntrack, восстановление правил
сериализовано; исправления объединены с IPv6, Telegram и управлением панели
в `feat/telegram-tunnel`. Установка обновляет весь комплект из этой ветки.

Добавлен C-helper для HTTP-редиректов на явную страницу блокировки провайдера:
он переводит такой запрос на HTTPS исходного сайта, не меняя обычные
редиректы авторизации. После последующих исправлений автоматического подбора
RuTracker открывается; повторная проверка текущего комплекта 01.10.2026:
HTTPS `/forum/index.php` — HTTP 200, 96 460 байт; HTTP перенаправляется на HTTPS.
Это проверка загрузки страницы, не гарантия прохождения любой проверки Cloudflare.
Состав первоначального ручного эталона и границы переноса сохранены в
[полевой записи](docs/field/rutracker-manual-working-plan.txt).

### Обновление IPv6

Добавлен нативный IPv6-путь для TLS 1.2, TLS 1.3 и QUIC: перехват, замер,
подбор, применение и сохранение обходов. IPv4 и IPv6 имеют отдельные
подтверждения; отключать IPv6 или принудительно переводить QUIC на TCP не нужно.
Обновление — той же командой установки выше, без удаления изученного состояния.
Для правил IPv6 требуется доступный `ip6tables` с NFQUEUE и connbytes;
неполный набор правил считается ошибкой, а не рабочей поддержкой IPv6.

Полевые проверки на ARM64-роутере: YouTube отвечает по IPv6 с принудительными
TLS 1.2 и TLS 1.3 (`curl`), HTTP/3 — отдельным клиентом на основе C-верификатора
D2K. Все три обхода сохранились и повторно сработали после перезапуска движка.
Google отвечает по IPv4 и IPv6. Независимые HTTP/3-клиент и сервер
проверены в изолированном Linux-стенде. На Android проверено видео YouTube
в 720p60 через Wi-Fi: QUIC к видеосерверу по IPv6, повторное открытие и
воспроизведение с 8-й минуты после перезапуска движка. Автопоиск для
`i.ytimg.com` подтвердил и сохранил IPv6/TLS-план существующей коробки.
[Подробности и границы проверки](docs/field/2026-09-29-ipv6-phone.md).
Другие модели роутеров требуют полевой проверки.

### Команды

```sh
/opt/etc/init.d/S99d2k status   # состояние компонентов
/opt/etc/init.d/S99d2k stop     # остановить D2K и снять его правила
/opt/etc/init.d/S99d2k start    # снова запустить
/opt/etc/init.d/S99d2k restart  # перезапустить
```

Если после включения появились проблемы с сетью, сначала выполните `stop`. Настройки находятся в `/opt/d2k/config`, журналы — в `/opt/d2k/log/`.

Для Instagram и WhatsApp Web:

```sh
/opt/d2k/d2k-instagram-dns.sh refresh       # обновить сейчас (до нескольких минут)
cat /opt/d2k/state/instagram-ip-hosts.tsv  # только записи, принадлежащие D2K
tail -n 30 /opt/d2k/log/instagram-dns.log
```

Ошибка DNS-обновления не означает автоматически, что VPS недоступен: журнал различает отказ запроса, недоверенный адрес/сертификат и ошибку сохранения на роутере. Не отключайте проверку сертификатов ради успешного статуса.

Чтобы удалить программу, но оставить конфигурацию и изученное состояние, добавьте `D2K_KEEP_STATE=1` перед командой `sh "$f"` в строке удаления. Обычная команда выше удаляет всё состояние D2K.

## Архитектуры

Для каждой цели собирается полный статический C-комплект: движок, контроллер, панель и Telegram. Отдельная установка OpenSSL-библиотек для этих бинарников не нужна; `openssl-util` и CA-сертификаты нужны установочным скриптам.

| Цель | Требования |
| --- | --- |
| ARM64 | AArch64 |
| ARM32 | ARMv7 и новее, little-endian, EABI, VFPv3 |
| MIPS / MIPSEL | MIPS32, big-/little-endian соответственно, soft-float |
| MIPS64EL | MIPS64, little-endian, N64 ABI, **нужен FPU** |
| x86 / x86-64 | i686 / x86-64 |
| PPC64 | 64-битный PowerPC, big-endian |
| RISC-V64 | RV64GC |

Для MIPS64EL установщик дополнительно проверяет наличие FPU и отказывается менять установку, если подтвердить его не удалось. Нативный MIPS64EL без FPU пока не поддерживается.

Проверки пакетов: запуск всех 36 бинарников под QEMU, отсутствие динамических зависимостей, криптография, QUIC-пакеты, разбор планов, OpenSSL и Telegram-сессии. MIPS32-сессии дополнительно проверены на эмулируемом CPU без FPU. Изолированный ARM64-тест проходит установку, обновление, безопасный отказ, остановку/запуск и полное удаление.

Это тестовые пакеты, **не подтверждение совместимости со всеми моделями**. Реальная установка ранее проверялась на ARM64; остальные устройства требуют полевых тестов. Эмуляция проверяет запуск и переносимость, но не драйверы Netfilter, NDM и производительность конкретного роутера. На всех моделях нужны Entware, NFQUEUE, connbytes и ipset. Lexra, ARMv5/ARMv6 и 32-битный PPC не поддерживаются; MIPS64 с 32-битным Entware получает пакет MIPSEL/MIPS согласно ABI Entware. Неизвестная архитектура вызывает явный отказ до остановки старой службы.

## Для разработчиков

D2K переносит сам «Поиск по домену» z2k на C, а не заменяет его другим алгоритмом. Полные требования: [D2K_SPEC.md](D2K_SPEC.md); история и ограничения: [D2K_HANDOFF.md](D2K_HANDOFF.md). Принятый владельцем MVP не означает завершение всех пунктов полного ТЗ, включая STUN и безымянный IP-трафик.

```sh
sh scripts/check.sh
make -C telegram test
make -C panel test
make -C relay-enroll test
sh scripts/lab-install.sh  # изолированная установка/удаление; нужен Docker
```

На роутере работают C-процессы `d2kd`, `d2kc`, `d2kpanel` и `d2ktg`. Серверный Telegram relay — существующий внешний сервис z2k; его Go-runtime не устанавливается на роутер. Для сборки нужны make, Perl, git и Zig **0.16.0**; для MIPS64EL используется **0.14.1**, поскольку 0.16.0 не линкует полный runtime этой цели. OpenSSL закреплён по commit.

```sh
ZIG_MIPS64EL=/path/to/zig-0.14.1 sh scripts/build-router.sh
# Или только нужные пакеты:
ARCHES="arm64 mipsel" sh scripts/build-router.sh
# Сборка существующих регрессий под те же CPU/ABI:
ZIG_MIPS64EL=/path/to/zig-0.14.1 sh scripts/build-router-tests.sh
# На Linux с qemu-user и binutils:
sh scripts/check-router-builds.sh
```
