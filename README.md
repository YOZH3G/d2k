# d2k — Dynamic2Keenetic

Обход DPI для роутеров Keenetic, который **ничего не знает заранее**.

Без поставляемых списков заблокированных доменов. Без предварительного
объявления сайтов заблокированными. Пользователь пользуется интернетом, d2k
наблюдает; когда соединение не проходит, d2k измеряет поведение блокировки,
подбирает преобразование и запоминает то, что сработало.

**Главное ТЗ — [D2K_SPEC.md](D2K_SPEC.md), редакция 14.09.2026.**
D2K — полный перенос самого «Поиска по домену» на C, автоматизированный
по живому трафику, а не новый поиск по его мотивам. Без Zapret/nfqws в
исполнении. TLS 1.2, TLS 1.3, QUIC и STUN исследуются своими путями;
для адресного трафика домен не обязателен. Найденное используется, пока
работает; при подтверждённой деградации поиск возобновляется.
Текущая реализация ещё не принята по этому ТЗ.
История архитектуры и передачи — в [D2K_HANDOFF.md](D2K_HANDOFF.md).
Здесь только то, что нужно, чтобы понять и запустить.

## Что он делает

1. Смотрит на транзитные соединения. Узнаёт TLS, вынимает имя цели.
2. Замечает подозрительное: подделанный сброс, повтор приветствия, молчание
   в ответ на приветствие.
3. Для подозрительного трафика проверяет собственное подходящее решение,
   затем при необходимости вызывает перенесённый «Поиск по домену» в
   исходном протоколе. Работающий прямой трафик не отправляет в подбор.
4. Сработавшее — записывает: модель поведения коробки, план и привязку цели.
   Не сработавшее не становится подтверждённой привязкой или вечным запретом.

«Сервер не ответил», локальная ошибка и исчерпание бюджета — разные исходы,
хотя ни один не подтверждает обход. Наблюдения нужны для выбора следующего
опыта, но не должны навсегда исключать цель из исследования: линия, маршрут
и DPI меняются. Требования к контексту и повторной проверке — в D2K_SPEC;
их реализация пока не завершена.

## Как это выглядит на живой линии

Клиент сходил один раз и получил отказ. Дальше без его участия:

```
подозрение по linkedin.com (сброс в ответ на приветствие): начат поиск
  примета: rst ttl=126 (сервер 122) tos=0x88 ipid=54321
по linkedin.com пробую plan-b08307c3, попытка 1
по linkedin.com поймана форма приветствия: 322 байт
по linkedin.com стучусь сам: форма клиента -> 130.211.32.14:443
по linkedin.com обмен пошёл: заведена коробка box-4c6254bf
```

От подозрения до применённого плана — 77 мс. Дальше цель открывается сразу,
а следующая цель с тем же поведением коробку **узнаёт** и новый подбор не
запускает.

## Устройство

Ниже описано текущее/историческое устройство, не подтверждение полной
приёмки MVP. Панель — отдельный C-процесс: она показывает состояние и
управляет жизненным циклом сервиса через фиксированные локальные команды.
Установка и управление проверяются в изолированном ARM64-контейнере.

Три процесса, и это намеренно: падение планировщика не должно ронять разбор
пакетов, а падение панели — ни то, ни другое.

| | язык | что делает |
|---|---|---|
| `d2kd` | C | видит пакеты: NFQUEUE, учёт потоков, разбор TLS и QUIC, исполнение планов |
| `d2kc` | C | каталог коробок, узнавание, подбор, зонды, оба транспорта |
| `d2kpanel serve` | C | панель состояния и start/stop/restart/reapply; узнанное читает из файла `d2kc` |

До 11.09.2026 подбором занимался Go-процесс `d2k serve`. Он удалён вместе со
своей половиной дерева: §12 требовал держать его ровно до тех пор, пока ядро на
C не пройдёт те же живые замеры. Переходная Go-панель заменена `d2kpanel`; она
знания не собирает — только показывает данные `d2kc`.

Язык выбран замером, а не вкусом: `docs/field/2026-09-05-stage0-implementations.md`.
C и Rust по скорости неразличимы, решил тулчейн — у `rustup` нет ни одной
MIPS-цели. Go в датапате выбывает по ресурсам: 22 % процессора против 15 и
5,1 МБ памяти против 224 КиБ.

На пакетном пути нет плавающей арифметики: MIPS-коробки идут без
сопроцессора.

## Установка MVP

Публичная тестовая сборка сейчас публикуется из ветки
`feat/telegram-tunnel` (это не стабильный релиз). Установщик предназначен для
Keenetic ARM64 с Entware и требует `curl`, `iptables`, `start-stop-daemon` и
поддержку NFQUEUE в ядре. Запускайте его по SSH на роутере от `root`. Сначала
скачайте и просмотрите скрипт, затем запустите его с той же веткой: он скачает
совпадающие runtime-файлы и ресурсы панели, проверит бинарники до замены,
сохранит существующую конфигурацию и запустит D2K.

```sh
REF=feat/telegram-tunnel
curl -fsSL "https://raw.githubusercontent.com/necronicle/d2k/$REF/scripts/install.sh" -o /tmp/d2k-install.sh
less /tmp/d2k-install.sh
D2K_REF="$REF" sh /tmp/d2k-install.sh
```

Установка включает активный режим (`MODE=apply`) и начинает обработку трафика.
Перед запуском убедитесь, что понимаете, как остановить D2K командами ниже.
Установщик не перезаписывает `/opt/d2k/config` при обновлении.

```sh
/opt/etc/init.d/S99d2k status   # состояние компонентов и правил
/opt/etc/init.d/S99d2k stop     # немедленно остановить D2K
/opt/etc/init.d/S99d2k start    # снова запустить
```

### Веб-панель и кнопки управления

После установки откройте `http://<LAN-адрес-роутера>:8090/` — например,
`http://192.168.1.1:8090/`. Установщик сам выбирает приватный адрес основного
LAN-интерфейса роутера; публичный WAN-адрес он не использует. Кнопки управления
работают прямо из этой панели и принимают запросы только с её собственного
origin.

У панели пока нет входа по паролю: любой клиент, имеющий доступ к ней в вашей
локальной сети, может видеть состояние D2K и нажимать управляющие кнопки. Не
открывайте порт 8090 из интернета. Для установки, где LAN IPv4 не удалось
определить, установщик остановится с явной ошибкой, а не станет слушать на всех
интерфейсах.

### Удаление

Полное удаление останавливает службу, снимает только правила и Instagram DNS-
записи D2K, удаляет панель, бинарники, конфигурацию и каталог изученных коробок.
Скачайте и проверьте скрипт перед запуском:

```sh
REF=feat/telegram-tunnel
curl -fsSL "https://raw.githubusercontent.com/necronicle/d2k/$REF/scripts/uninstall.sh" -o /tmp/d2k-uninstall.sh
less /tmp/d2k-uninstall.sh
sh /tmp/d2k-uninstall.sh
```

Если хотите оставить конфигурацию и каталог коробок для будущей установки,
запустите его с `D2K_KEEP_STATE=1 sh /tmp/d2k-uninstall.sh`. По умолчанию
удаляется всё содержимое `/opt/d2k`.

До установки на роутер полную установку и удаление можно проверить в чистом
ARM64-контейнере:

```sh
sh scripts/lab-install.sh    # нужен Docker; роутер не трогается
```

Непроверенными без отдельного полевого прогона остаются поведение NDM,
переживание перезагрузки на Keenetic и применение QUIC-обхода на реальном
клиентском трафике. Текущие TLS 1.3, TLS 1.2 и QUIC приняты владельцем как
состав MVP; лабораторные проверки не выдаются за полевое подтверждение.

Чтобы пересобрать публикуемый комплект из исходников:

```sh
make -C datapath d2kd-linux-arm64
make -C core d2kc-linux-arm64
make -C panel d2kpanel-linux-arm64 VERSION=0.1.0-mvp
```

## Сборка и проверка

```sh
sh scripts/check.sh          # всё: формат, vet, тесты C и Go, санитайзеры,
                             # чужой компилятор, кросс-сборка, shellcheck
make -C datapath d2kd-linux-arm64   # служба датапата под роутер
sh scripts/build.sh             # Go dev/reference артефакты и C runtime под ARM64
sh scripts/lab-install.sh       # установка целиком, в контейнере (нужен Docker)
sh scripts/lab-transit.sh       # клиент ЗА NAT: обход обязан дойти до него
```

`scripts/check.sh` — единственный вход в проверку. Звать его надо через `&&`:
точка с запятой пропускает красный вердикт дальше, и это уже стоило коммита
с непроходящим форматом.

## Полевой прогон

```sh
D2K_ROUTER=… D2K_SSH_PASS=… D2K_MODE=apply D2K_MARK=45 \
D2K_SRC=<адрес клиента> D2K_LEARN=1 \
sh scripts/field-observe.sh
```

Скрипт собирает, доставляет, ставит правила, поднимает службу и контроллер,
собирает вывод и **убирает за собой** — правила снимаются по жетону запуска,
каталог и журналы забираются, временное на роутере удаляется. Ничего не
пишется на флеш-накопитель.

Опыт обязан быть узким: без `D2K_SRC` или `D2K_DST` активный режим не
запускается. На роутере живут чужие устройства, и десинк всего 443-го порта —
не эксперимент, а авария.

## Происхождение

Донор опыта и части решений — [z2k](https://github.com/necronicle/z2k),
MIT, тот же автор. Перенесены не исходники, а измеренное: рабочее плечо
записано форматом Plan, ошибки донора перечислены в D2K_HANDOFF §6.2 и
исправлены, а не унаследованы.

nfqws и Lua-библиотеки Zapret не являются компонентами d2k.
