# Как выпустить релиз D2K

Выпуск — один ручной запуск GitHub Actions с `main`. Роутеры с
автообновлением ставят его сами ночью 03:00–05:00 по своим часам или по
кнопке в панели.

## Порядок

1. Изменения влиты в `main`, CI на `main` зелёный.
2. GitHub → **Actions** → **D2K release** → **Run workflow**, ветка `main`.
   В поле «Что изменилось» — пара строк для людей: их покажет панель.
3. Ждать зелёного запуска (~30–40 минут: OpenSSL для `d2ktg` собирается на
   девять арок с нуля).

Всё. Никаких каналов, переподписей по расписанию и пробных запусков.

### Что делает workflow (`.github/workflows/release.yml`)

1. Собирает `d2kd`, `d2kc`, `d2kpanel`, `d2ktg` на девять арок
   (`scripts/build-router.sh`) и гоняет их под QEMU
   (`scripts/check-router-builds.sh`).
2. Упаковывает `d2k-<арка>.tar.gz` (`scripts/package-release.sh`): бинарники
   арки, `files/`, страницы панели и установщик `scripts/install.sh` — то
   же, что ставит ручная установка.
3. Пишет `latest.json` (номер выпуска, версия, описание, sha256 каждого
   архива) и подписывает его ключом Ed25519 из окружения `d2k-signing`,
   сразу проверяя подпись ключом, закреплённым в `files/d2k-update.sh`.
4. Публикует GitHub-релиз `d2k-<дата>-<время>-<коммит>` и помечает его
   последним (latest).

### Что делает роутер (`files/d2k-update.sh`)

1. Берёт `releases/latest/download/latest.json` и `.sig`, проверяет подпись
   закреплённым ключом. Не сошлась — ничего не ставит.
2. Номер совпадает с установленным (`/opt/d2k/release-id`) — ничего не
   делает.
3. Скачивает архив своей арки, сверяет sha256 с подписанным `latest.json`.
4. Сохраняет текущие бинарники, скрипты, панель и `config` в
   `/opt/d2k/.update/previous.tar`.
5. Запускает установщик из архива (`D2K_LOCAL`), он останавливает и
   запускает службу. Затем минуту ждёт и проверяет, что датапат,
   контроллер и панель живы.
6. Успех — копия удаляется: на роутере остаётся только новая версия.
   Отказ — копия возвращается, служба перезапускается, выпуск помечается
   плохим: ночью он больше не ставится, вручную из панели — можно.

Журнал — `/opt/d2k/log/update.log`, состояние для панели —
`/opt/d2k/state/update.json`. Ночная установка выключается тумблером в
панели (`AUTOUPDATE=0` в `config`): тогда ночью только проверка.

## Правила

**Выпуск не переиздаётся.** Нашли дефект — выпускайте следующий. Роутер,
на котором выпуск не прошёл проверку, сам вернул прежнюю версию.

**`config` и каталог переживают обновление.** Установщик не трогает
существующий `config` и `state/`. Новые ключи конфигурации добавляйте так,
чтобы их отсутствие означало прежнее поведение.

**`builds/` в репозитории — для ручной установки из README.** Она ставит
бинарники из `builds/` ветки `main` и страницы панели из исходников той же
ветки. Если менялся API панели или протокол между процессами, обновите
`builds/` вместе с кодом, иначе ручная установка поставит старый бинарник
под новые страницы. Роутеры с автообновлением получают код из выпуска.

## Ключ подписи

Ed25519. Закрытая часть:

- на машине владельца — `~/.ssh/d2k_release_signing_ed25519.pem` (0600),
  открытая — рядом, `…pub.hex`;
- на GitHub — секрет `D2K_ED25519_PRIVATE_KEY` окружения `d2k-signing`.

Открытая часть — переменная репозитория `D2K_SIGNING_PUBLIC_KEY` и строка
`KEY=` в `files/d2k-update.sh`; workflow проверяет, что они совпадают. В
репозиторий закрытый ключ не кладётся никогда.

Ключ лежит в секрете Actions: захват репозитория с доступом к окружению
`d2k-signing` даёт и подпись. Строже — обязательное подтверждение владельцем
(Settings → Environments → `d2k-signing` → Required reviewers).

**Потеря ключа** — роутеры больше не примут ни одного выпуска; поможет
только ручная переустановка с новым ключом в `d2k-update.sh`. Храните копию.

## Проверка

Перед выпуском, если менялись `files/`, установщик или обновление:

```sh
node scripts/test-update.cjs     # подпись, установка, возврат, тумблер
sh scripts/check.sh              # всё остальное
```

После выпуска:

```sh
curl -fsSL https://github.com/necronicle/d2k/releases/latest/download/latest.json
```

показывает новый `release_id`. На роутере — кнопка «Проверить» в разделе
«Обновления» панели или `/opt/d2k/d2k-update.sh check`.

## Если что-то пошло не так

**Workflow упал до публикации** — релиза нет, роутеры ничего не видят.
Исправьте и запустите снова.

**Пользователь пишет, что обновление не встало** — в панели виден итог и
причина; подробности в `/opt/d2k/log/update.log`. Прежняя версия к этому
моменту уже возвращена. Если возврат тоже не удался, копия лежит в
`/opt/d2k/.update/previous.tar` (распаковывается в `/`), и это сказано в
журнале.
