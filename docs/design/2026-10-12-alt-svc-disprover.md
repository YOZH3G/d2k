# alt-svc — опровергатель долга по QUIC, а не повод спрашивать (12.10.2026)

## Исправленная премиса

Сначала я предлагал обратное: увидел у цели `alt-svc: h3=...` — заведи по ней
вопрос по QUIC. **Это неверно, и предложение снято.**

Во-первых, оно не нужно. Поиски по QUIC и так ограничены наблюдённым трафиком:
в полевом прогоне j строки `quic` есть ровно у тринадцати имён, а у
`flibusta.is` и `www.tampermonkey.net` — тех самых, что h3 не объявляют, — их
нет вовсе (`docs/field/2026-10-11m-run-j-measured-vs-fallback.md`, приложение с
таблицей). Заголовок добавил бы ровно то, что уже сделано проводом.

Во-вторых, оно запрещено. Спрашивать по заголовку — значит заводить подбор по
имени, которое в эту минуту, может быть, прекрасно работает напрямую. §0 ТЗ:
«Рабочий прямой трафик не запускает подбор. Подозрение не равно блокировке.»
«h3 объявлен» — это вообще не подозрение, это объявление сервера о себе.

Полезным осталось **обратное направление**: заголовок ОПРОВЕРГАЕТ ДОЛГ.

> Если цель h3 не объявляет, браузер по QUIC туда не пойдёт. Значит записанный
> на неё долг по QUIC беспредметен: в таблице прогона по ней не должно
> появляться ни строки `quic`, ни заявления «QUIC не взят».

Опровергатель не добавляет работы — он снимает с учёта несуществующую. Это
разрешено тем же §0, который запрещает первое.

## Свойства факта, из которых следует, как его можно использовать

`alt-svc` — **внешний факт на момент чтения**, и в нём три свойства, каждое из
которых сужает, что на нём можно строить:

1. **Он живёт `ma` секунд и может появиться позже.** `ma=86400` — сутки,
   `ma=2592000` — тридцать суток. «Не объявляет» верно на момент чтения, не
   навсегда. Поэтому список — вход прогона, а не константа.
2. **Он приходит внутри TLS.** Его читает браузер или свой зонд; **датапат его
   не видит и видеть не может**, значит опираться на него в проводе нельзя —
   только в учёте после замера.
3. **Он может называть другой порт**: `h3=":8443"`. Тогда QUIC не беспредметен
   — он просто не на 443, и отсутствие нашего трафика на 443 ничего не
   опровергает.

Четвёртое, измеренное при проверке 12.10: **отсутствие h3 у документа не
означает, что на странице нет h3 вовсе.** У `flibusta.is` документ пришёл по
h2, а четыре подзапроса (чужих origin) ушли по h3. Опровергатель работает по
ИМЕНИ (origin), по которому читался заголовок, и ни на какое другое имя не
распространяется — в том числе на поддомены и на родительскую зону.

## Числа замера 12.10.2026

Прочитано с мака владельца, то есть из LAN за роутером с живым D2K.

**h3 объявляют** (`alt-svc` прочитан, в нём есть `h3`):

| Имя | alt-svc |
|---|---|
| nnmclub.to | `h3=":443"; ma=86400` |
| katzauction.com | есть h3 |
| www.cloudflare.com | `h3=":443"; ma=86400` |
| www.google.com | `h3=":443"; ma=2592000,h3-29=":443"; ma=2592000` |

**h3 НЕ объявляют** (ответ пришёл, заголовка в нём нет) — только по этим именам
опровергатель и применим:

| Имя | что было в ответе |
|---|---|
| flibusta.is | документ h2 200, `alt-svc` отсутствует |
| www.tampermonkey.net | документ h2 200, `alt-svc` отсутствует |

**Сказать нечего** — в тот момент TCP-путь для curl был закрыт, значит
`alt-svc` НЕ ПРОЧИТАН; это диагностика состояния, а не вердикт:
`rutracker.org`, `lostfilm.tv`, `fost.club` (RST на рукопожатии TLS),
`kinozal.tv` (мгновенный отказ, 2 мс), `adguard.com` (таймаут 10 с).

Эти имена **не вносить** в список опровергателя ни под каким видом: «мы не
смогли прочитать» и «сервер не объявляет» — разные вещи, и из первого второе не
следует.

Источник первых чисел — `docs/field/2026-10-12c-quic-handshake-name-control.md`
(раздел «Побочное, тем же замером»). Повторная проверка 12.10 настоящим
браузером через `scripts/live-protocol.mjs` (ниже) дала то же самое по пяти
именам, которые удалось открыть.

## Как это включается в таблице прогона

`scripts/field-table.py` получил **явный вход** и без него не меняет поведение
ни в чём (проверено: вывод по тому же журналу байт-в-байт тот же):

```
scripts/field-table.py d2kc.log --no-h3 flibusta.is,www.tampermonkey.net
scripts/field-table.py d2kc.log --no-h3-file no-h3.txt     # имя на строку, «#» — коммент
```

Числа выше — **значение по умолчанию ЭТОГО ДОКУМЕНТА, а не кода**. В коде
списка нет и не будет: по имени h3 не угадывается, по зоне не наследуется, и
через сутки `ma` он может стать другим.

Что делает флаг:

- строка `quic` по имени из списка помечается в таблице
  `quic (беспредметно: h3 не объявлен)`;
- такая строка **не попадает в «Долг замера»** — долга по QUIC у неё нет;
- она попадает в отдельный раздел «Беспредметно по QUIC», где рядом печатается
  потраченное число единиц зондов: беспредметно не значит бесплатно, и строка
  там — это отчёт о ЛИШНЕЙ работе, а не о промахе классификатора;
- если по именам из списка строк `quic` в журнале нет вовсе, печатается именно
  это («опровергать нечего») — так выглядит правильный прогон, как j;
- имя из списка, которого в журнале нет, называется вслух. Сравнение **точное**
  по имени строки: при `--sites` строка могла свернуться к родительскому имени,
  и тогда опровергатель молча не применяется — это сделано нарочно, потому что
  «www.X без h3» ничего не говорит про X;
- под разделом всегда печатаются три свойства факта из списка выше, чтобы
  читатель таблицы не принял их за измеренную D2K величину.

## Как факт измеряется тем же инструментом, что и живой критерий

`scripts/live-protocol.mjs` печатает `alt-svc` документа третьей строкой по
каждому имени. Протокол отладки его отдаёт: `Network.responseReceived` несёт
`params.response.headers` со всеми заголовками ответа как есть. Проверено
12.10 на Chrome 154.0.8037.98:

```
www.cloudflare.com     1-й: h3/200 v4 104.16.123.96 зап.135 [h3×134 h2×1]
                       2-й: h3/200 v4 104.16.123.96 зап.139 [h3×137 h2×2]
                       alt-svc: h3=":443"; ma=86400
www.google.com         1-й: h3/200 v4 142.251.155.119 зап.35 [h3×32 data×1 h2×2]
                       2-й: h3/200 v4 142.251.155.119 зап.30 [h3×27 h2×2 data×1]
                       alt-svc: h3=":443"; ma=2592000,h3-29=":443"; ma=2592000
flibusta.is            1-й: h2/200 v4 179.43.150.83 зап.27 [h3×4 h2×22 data×1]
                       2-й: h2/200 v4 179.43.150.83 зап.23 [h2×22 data×1]
                       alt-svc: НЕТ
www.tampermonkey.net   1-й: h2/200 v4 46.4.58.236 зап.1 [h2×1]
                       2-й: h2/200 v4 46.4.58.236 зап.1 [h2×1]
                       alt-svc: НЕТ
nnmclub.to             1-й: h2/200 v4 188.114.96.3 зап.71 [h2×67 http/1.1×4]
                       2-й: h2/200 v4 188.114.96.3 зап.75 [h2×71 http/1.1×4]
                       alt-svc: h3=":443"; ma=86400
```

Значение печатается по обоим заходам: «нет в первом ответе» и «есть во втором»
— разные вещи, и если они разошлись, печатается `первое → второе`.

Две строки из этого вывода читаются сразу и обе согласуются с замерами 12.10:

- **nnmclub.to h3 объявляет, а документ взял по h2.** Ровно это и описано в
  `2026-10-12c`: браузер h3 пробует, рукопожатие QUIC к этому имени не
  завершается, браузер молча падает на TCP. Долг по QUIC у nnmclub ПРЕДМЕТЕН —
  опровергатель его не трогает.
- **www.tampermonkey.net h3 не объявляет**, а D2K по памяти 12.10 гонял по
  этому имени перебор по QUIC десятками зондов. Такой строке в долге не место,
  но в отчёте о лишней работе — место.

## Чего здесь нет

- **Никакого автоматического чтения `alt-svc` прогоном.** Таблица его не
  добывает; она принимает прочитанное. Добывает его браузерный замер
  (`live-protocol.mjs`) или свой зонд — вручную и под дату.
- **Никакого влияния на планировщик и датапат.** Это инструмент координатора,
  правка в `scripts/`, и она не меняет ни одного решения о подборе.
- **Никакой проверки, что имя из списка действительно не объявляет h3.**
  Ответственность на том, кто передаёт список; дата чтения — часть факта.
