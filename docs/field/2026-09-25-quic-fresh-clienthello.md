# Передача: свежий QUIC ClientHello между arm-вопросами — 25.09.2026

## Что изменено — продолжение 25.09

Оригинальный Go `internal/quicprobe/arms.go:askArms` вызывает `buildInitial`
внутри builder каждого отдельного arm-вопроса. C runtime раньше подавал один
`trigger` на все эти вопросы; нижний транспорт обновлял QUIC CID, но TLS
ClientHello (включая `client_random` и X25519 key share) оставался прежним.

`core/props.c:original_probe` теперь извлекает исходные и контрольные SNI и
для каждого вопроса строит новый Initial через `d2k_quic_probe_initial` — C
порт профиля измерительного `buildInitial`. Неудача извлечения SNI или сборки
считается незаданным/неизмеренным вопросом (`sent=0`), без fallback к старому
снимку. Байт-в-байт сохранённые arm blob/copy count передаются как раньше.

Продолжен нижний уровень повторов: `core/props.c:original_probe` теперь
передаёт вопрос и SNI в отдельный `d2k_quic_ask_arm_hook`. Он строит новый
Initial непосредственно для каждой параллельной попытки в `quic_ask_ex`, до
отправки. После сборки к каждой попытке применяются прежние параметры этого
вопроса: blob отдельными датаграммами и их число, TTL для blob либо сырой
фрагментационный план. Все попытки по-прежнему отправляются до ожидания
ответов. Снимочные пути оставлены на прежней ветке `d2k_quic_hello_recid`.

## Регрессия

`core/test_quic_run_order.c` снимает расшифрованный ClientHello на входе
измерительного хука. До правки `make test-quic-run-order` завершался ошибкой:
все arm-вопросы несли одинаковое приветствие, несмотря на различающийся CID.
После правки проверка проходит и видит разные ClientHello.

`core/test_quic_fresh_repeats.c` принимает реальные UDP-датаграммы на loopback:
три параллельные попытки, две отдельные копии blob перед каждой и Initial с
`fresh.example`. Тест расшифровывает каждый ClientHello и сравнивает содержимое.
При возврате к сборке одного Initial на весь вопрос (с CID refresh на повторы)
регрессия падала на трёх парах идентичных ClientHello; после переноса сборки
внутрь повтора проходит. Тест включён в `make check` и cross-link.

## Продолжение: снимок, пришедший во время поиска

QUIC SHAPE хранится вместе с именем, разобранным именно из этих байт.
Если снимок той же цели приходит во время `ASKING`, текущий Run продолжает
использовать неизменённый вход; после его возврата результат отбрасывается,
и один раз запускается новый поиск с точными байтами Initial. Если снимок
пришёл во время проверки известных планов, но все они не подошли, до запуска
свежего классификатора применяется тот же exact-snapshot путь. Регрессия в
`test_sched` удерживает Run, посылает снимок и проверяет оба свойства:
исходный вход не меняется, повтор получает ровно захваченные байты. Снимок
соседнего SNI не может стать снимком цели.

Не покрыт снимок, прибывший во время `VERIFY` уже установленного нового
кандидата: он сейчас не отменяет доказательство и не перезапускает поиск.
Безопасное снятие только принадлежащего этому опыту кандидата ещё не решено;
широкий `DEL_NAME` может задеть другое подтверждённое решение, поэтому он не
добавлен как shortcut.

## Что всё ещё не перенесено

Свежесть ClientHello между arm-вопросами и повторами теперь покрыта раздельными
wire-level тестами. Поздний снимок при `ASKING` и перед свежим поиском после
провала известных планов покрыт scheduler-регрессией, но не закрывает
`VERIFY`, сборку Initial между UDP-датаграммами, не-AES профиль или оставшиеся
сверки вопросов/контроля и адресного QUIC-пути с оригиналом.

Полевые тесты через роутер/провайдера намеренно не запускались: для них
требуется отдельное согласование с владельцем и его переключение z2k. Реальное
QUIC-приложение и сквозная установка этой правкой не проверялись.

## Проверки

- Красный/зелёный: `make test-quic-run-order` — красная проверка повторного
  ClientHello до правки, затем `original Run order: passed`.
- `make test-quic-original-arms test-quichello test-quicprobe
  test-quic-run-order` — все четыре прошли после реализации.
- `make test-quic-fresh-repeats test-quic-run-order test-quic-original-arms
  test-quichello test-quicprobe` — все пять прошли после продолжения.
- Полный `make check` — прошёл после включения `test-quic-fresh-repeats` в цель.
- `make cross` сначала выявил отсутствующие `voice.c`/`stun.c` в cross-link
  рецептах `test_sched` и `d2kc`; рецепты исправлены для обоих CPU и static ARM64.
- После исправления recipes `make cross` прошёл: ARM64 musl и MIPS little-endian
  собираются/линкуются. Это не запуск тестов на целевых CPU и не поле.
- `make cross` после добавления loopback-регрессии прошёл: тест линкуется для
  ARM64 musl и MIPS little-endian; бинарники под целевыми CPU не запускались.
- Эти проверки не запускают бинарник на Keenetic и не заменяют Linux wire/lab,
  реальный QUIC app либо полевую приёмку.
