# D2K MVP — аудит доказательств на 27.09.2026

Этот файл не объявляет MVP завершённым. Он фиксирует, какое утверждение чем
доказано и где доказательства пока недостаточно сильны. Полевое дополнение от
27.09 — [TCP/TLS вертикаль и QUIC-наблюдение на роутере](2026-09-27-router-field-tcp-quic.md);
оно обновляет соответствующие статусы ниже, но не закрывает пункт 5 целиком.

### Ретесты 27.09 после обновления отчёта

Контролируемая деградация и рестарт описаны с сырыми журналами в
[полевом дополнении](2026-09-27-router-field-tcp-quic.md). Она также поймала
ошибку d2kc persistence: старое dirty-условие сравнивало только число
bindings, поэтому замена Plan существующего домена терялась. Добавлен
process-local `d2k_catalog.revision`; `test_sched` проверяет её увеличение,
и на Keenetic фактически увидено `каталог сохранён (изменение 2)`. Затем новый
runtime загрузил сохранённый one-box/two-plan каталог и дал 5/5 HTTP 200.

Активный TLS 1.2 прогон принудительно ограничил клиент `--tls-max 1.2` на
YouTube IP, который напрямую timeout-ил. Получено 6 timeout → 6 HTTP 200;
verifier явно сообщил TLS 1.2 и привязка была записана под отдельную форму.
Это reuse готовой коробочной стратегии, не cold search TLS 1.2.

После этих изменений повторены `make -C core test_sched`,
`make -C core d2kc-linux-arm64`, `make -C datapath cross`,
`sh -n scripts/field-observe.sh`, shellcheck и `git diff --check` — всё прошло.
Полный `sh scripts/check.sh` завершился `ВСЁ ЗЕЛЕНО` непосредственно перед
revision-патчем; полный suite после revision ещё следует повторить, прежде чем
называть workspace целиком зелёным.

## Запрещённые сокращения при продолжении

- не подменять split replay одним склеенным UDP-пакетом;
- не вести STUN или неизвестный UDP через QUIC-зонд;
- не считать `APPLIED`, обычный UDP-ответ или ServerHello доказательством
  прикладного успеха без протокольного контекста;
- не включать роутерные lab-скрипты без отдельного согласования владельца.
