# План датапата повторяет посылки сырого зонда — 09.10.2026

База: main, `2d88080aee0e449e68638d37e2741d800cbb3bdf` (9 коммитов
поверх origin/main). Падающий тест: `1597739`. Исправление — коммит,
содержащий этот отчёт (его hash получить через `git log -1`).

До работы и после неё остаётся чужой незакоммиченный вынос
`d2k_poison_sends()`: detect/include/d2k_detect.h, detect/poison.c,
detect/raw.c, detect/test_raw.c. Эти файлы не редактировались и в коммиты
задачи не включены. Тест зависит от этого выноса: отдельно от dirty-дерева
коммиты задачи пока не являются самостоятельной сборкой.

## Воспроизведение и исправление

`make -C core test-probe-plan` до исправления: exit 2, 216 несовпадений
(тест exit 1). Восемь входов: 512, 1400, 1401 и 2048 байт, с SNI и без.
Каталог — 85 гипотез `d2k_poisons()`, вопросы — непосредственно
`prop_probes()` из detect/props.c (11; вопрос до конца SNI без имени
не задаётся, как в runtime). Длины фальшивок и перекрытий проверяются
с сегментацией D2K_ARM_SEGMENT_MAX, как raw_send().

Расхождения:

- 212 случаев seqovl без disorder: сборщик добавлял разрез +1, которого
  нет в замере. Затронуты seqovl-1; seqovl-hello;
  fake-x{7,4,2}+seqovl-{hello,681}; fake-x{7,4,2}+ttl62+seqovl-hello;
  seqovl-{2,4,8,16,64,336,681} с +hello и без; вопрос seqovl-sni.
  Теперь перекрытие и приветствие идут одной посылкой, длинная посылка
  режется только по потолку сырого отправителя.
- 4 случая disorder-pos2 без SNI: план требовал имя, хотя зонд режет
  относительно начала данных. Для безымянного входа сборщик теперь
  указывает измеренные координаты входа; именованный контракт сохранён.
- Полный core check выявил также три устаревших утверждения
  core/test_plantlv.c, требовавших форму донора multisplit(pos=1).
  Обновлены вместе с core/test_measured.c по форме сырого зонда.

Мост отвергает md5, syndata, oob; тест выводит список и пропускает их.
Всего 40 пропусков на восьми входах (включая повторные вопросы md5/syndata).
Остальных расхождений в проверенных входах нет.

Тест проходит мост → measured builder → TLV → load → apply. Сравнивает
порядок, seq/seq_shift, тип посылки, байты приставки и данных, poison,
TTL, wire profile и паузы перед посылками. tail_ms сырого списка — ожидание
перед чтением без последующей посылки; оно не является действием на проводе
и не сравнивается с d2k_actions.

## Границы и продолжение

Это локальная проверка посылок/исполнителя, не полевое доказательство успеха
приложения и не закрытие MVP. Роутер не трогали, push не выполняли.
Linux aarch64/mipsel cross проверяет компиляцию detect, не живую NFQUEUE.
Следующий пункт утверждённого плана — TCP-MD5 в датапате; поле и выпуск
требуют отдельного распоряжения владельца. Перед переносом коммитов
согласовать с владельцем исходного выноса включение detect-изменений.
