# Замер исполняет свой Plan — 10.10.2026

База: `main`, `93c6555350b5c43e71ed5372c2cc50cfe1be891b`, рабочее дерево
перед началом чистое. Ревизия исправления: `1aeee691a6c41165b4e745749001d65a8de47c04`. Документация
идёт отдельным следующим коммитом. На ревизии кода dirty только документы
этой передачи; после отдельного документационного коммита дерево чистое.
Только локальная работа; push, обращений
к роутеру, развёртывания и полевых запросов не было.

## Основание и граница вывода

Полевое свидетельство предоставлено владельцем: на rutracker.org и семействе C
вопрос «ECH-приветствие под меткой» проходит 3/3, но вооружённый им план получает
RST. Рабочий `plan-680fbe00` известен из [разбора 10.10](2026-10-10-tcp-block-analysis.md).
Повторного полевого опыта в этой задаче нет. Ни положительный ответ измерителя,
ни локальное равенство пакетов не означают успешного приложения или закрытия MVP.

На `93c6555` существовали две программы одного воздействия:

1. `detect/classify.c` / `detect/props.c` → `d2k_raw_probe_poison_family` →
   `d2k_poison_sends` → `raw_send` / `raw_send_urg` → `build_ip_tcp` → `sendto`.
2. `detect/bridge.c:d2k_arm_from_poison` →
   `core/compose.c:d2k_arm_plan_measured_cap` → `plantlv` →
   `datapath/plan_parse.c` → `plan_apply.c` → `wire.c:d2k_wire_build` → raw sink.

Старый `core/test_probe_plan` сравнивал действия датапата с описаниями посылок,
но не вызывал сырой runtime и не сравнивал конечные IP/TCP-пакеты. OOB он вообще
заканчивал после проверки DROP. В частности, слова «ровно plan-680fbe00»
в комментарии прежнего теста не подтверждались полным текстом/ID.

## Карта расхождений и потенциального дрейфа

| Участок | Сырой замер / прежний measured-arm | Рабочий C-план / датапат |
| --- | --- | --- |
| Представление воздействия | `d2k_poison_sends` отдельно от compose | Независимый текст Plan, повторный выбор порядка и разрезов |
| Fake payload | Префикс ECH + `0x0f` до `2 × trigger_len` | Только ECH-шаблон, для hcaptcha.com 675 байт |
| TLS modifiers | Нет | `tlsmod=rnd,dupsid`: random/SID, копирование реального SID при равной длине; одна модифицированная приманка на все повторы |
| Wire profile | `detect-tcp-v1` | `tcp-template-v1` |
| TCP timestamps/options | У fake TS=1/TSecr=0; у настоящих данных нет options; MD5 замещает options | Options из контекста потока, fake TSval−1000 с сохранением echo; отсутствие согласованного TS — отказ |
| IPv4 ID/DF, TTL, window | Случайный ID, DF=0, TTL=64 и окно 65535 | Template берёт ID/TTL/window из контекста, DF=1; legacy-профиль имеет третьи правила ID |
| Checksum/poison | Собственный pseudo-header, MD5 и badsum XOR 0xbeef | Отдельный сборщик; вне detect-профиля badsum инвертирует checksum. IPv6 не допускает IPID-zero |
| Сегментация | Каждая raw-посылка режется по 1400 | `segment 1400` и дополнительно доступный route cap реальной сессии; приставка+payload должны резаться как одна последовательность |
| Порядок и split | Собственные ветки reverse, forward +2, overlap, fake-between | Якоря Plan, порядок/pace/settle и разрезы вычислялись повторно |
| Повторы/время | Для C fake×8, gap=0, затем 15 мс перед настоящими байтами | Для `680fbe00` fake×8, gap=0, **без settle**, split +2 forward |
| URG | Три raw-посылки, свой указатель и seq+1; raw режет длинный хвост | Ранний return OOB обходил назначение wire profile и сегментацию общего executor |
| Контекст | Адреса, порты, seq/ack собственного TCP-зонда | Контекст захваченного клиентского пакета, TLS SID, timestamps, PMTU; равенство имеет смысл при одинаковом входе |
| Отказы | Сырой отправитель мог измерить воздействие, которое Plan не выражает | Нельзя превращать отказ компиляции/исполнения в отрицательный ответ коробки или молча слать иное воздействие |

Не каждая строка была отдельным полевым дефектом. Это карта мест, где два
исполнителя могли расходиться; симптом C воспроизведён локальными тестами.

## Один исполняемый источник

Выбран единый путь исполнения, разрешённый постановкой задачи: **сам
сериализованный Plan является программой замера**, а не посмертной ручной
сборкой по похожему набору флагов.

- Чистые сборщики measured/RX вынесены из сетевого `core/compose.c` в
  `core/measured.c`, чтобы standalone detect мог использовать их без
  планировщика и link-сокета. Существующий `plantlv.c` остаётся единственным
  сериализатором текста в TLV.
- `raw_send_plan` переводит гипотезу тем же `d2k_arm_from_poison`, собирает Plan,
  загружает его тем же parser и вызывает **те же** `d2k_plan_apply` и
  `d2k_wire_build`, которые обслуживают датапат. На границе остаются только
  задержка и отправка готового пакета в сокет. При отказе нет другого отправителя.
- После успешного замера bridge сохраняет owned параметры/байты приманки;
  scheduler вызывает тот же чистый сборщик с теми же данными. `send_cap` может
  отказать в применимости, но не переписывает доказанное воздействие.
- C-arm и RX-лестница используют одну функцию `template_plan`. Для исходной
  приманки это побайтно тот же текст/TLV и ID **`plan-680fbe00`**. Имя другой
  измеренной приманки сохраняется из входа, не заменяется hcaptcha.com.
- `d2k_poison_sends` и его типы удалены из продуктового пути; прежний алгоритм
  сохранён только в `detect/tests/legacy_sends.h` как независимый оракул
  совместимости остальных гипотез. Это не второй runtime.
- Raw сохраняет согласованные timestamps SYN-ACK для собственного контекста
  template-пакетов. Прямой контроль, SYN/ACK рукопожатия и диагностический
  SYN-data остаются отдельно: они не являются вторым исполнителем обходного
  Plan; SYN-data по-прежнему не может стать arm.

При расширении теста найдены и исправлены края общего пути:

- Предел trigger теперь общий и равен **прежнему** raw-пределу 16384, а не
  ошибочно пределу owned-приманки 2048. Размер live snapshot/очереди не менялся.
- OOB проходит общую финализацию, wire profile и сегментацию; срочный байт,
  номера последовательности и исходные данные сохраняются.
- Любой локальный отказ получает сообщение; `props` не меняет свойства и
  не добавляет отвеченную гипотезу при `rc < 0`.

## Регрессии: сначала красные, затем зелёные

1. `core/test_probe_plan.c`: весь C-текст и TLV против RX-ступени 0, отдельно
   FNV-ID `680fbe00`. На исходном `93c6555`: exit 1, arm имеет ID `0e3148df`.
   После исправления: 0 mismatches.
2. `detect/test_raw.c`: вызывается настоящий `d2k_raw_probe_poison_family`,
   включая dial/send loop; OS-сокеты/правила/ожидание/энтропия подменены
   локальным стендом. Перехват `sendto` сравнивается с независимым выполнением
   загруженного Plan: длина, **весь пакет memcmp**, количество и назначенная
   задержка. Для C эталон — RX-план, не описание посылок измерителя.
   На `93c6555`: сборка exit 0, тест exit 1 на конечных пакетах.
3. Матрица runtime: C + 84 выразимые гипотезы каталога; размеры
   675/1400/1401/2048/**2049/16384**; IPv4/IPv6 (невозможный IPv6 IPID-zero
   исключён по существующему протокольному контракту). Энтропия обоих запусков
   одинакова; поля пакетов не нормализуются и не вырезаются из сравнения.
4. Проверки отказа без TS и непредставимой/отсутствующей приманки. Ошибка не
   должна оставлять старую строку или переходить к запасному сборщику.
5. `test_repeats`: все вопросы с локальным отказом сохраняют неизвестные
   свойства и пустой `answered`. До защиты `apply_set` тест печатал «ПРОВАЛ»
   и возвращал exit 1; после — проходит.
6. Исторический `test_probe_plan` расширен до 16384 и теперь проверяет OOB
   полностью. До общей финализации он падал на wire profile OOB. Старый
   предел owned-overlap/decoy 2048 остаётся явным отказом, не усечением.

Падение без исправления проверялось перед продуктовой правкой и повторно в
отдельном `git archive 93c6555` с текущими тестами. В архиве исходники
принудительно `touch`, бинарники собраны заново прямым `cc` из `.c`, без
использования `.o` текущего дерева. Основное дерево и ветка не переключались.
`CHECK` копит ошибки, итоговый exit проверен; зелёного вывода в конце недостаточно.

Новый runtime-тест входит в `detect check`, C golden и исторический oracle —
в `core check`. Сообщения raw-теста о правилах RST/xt_comment порождены моками;
тест не вызывает системный firewall и не посылает пакеты в сеть. Linux cross
проверяет сборку и линковку, не выполнение. Сценарии `lab-*` не запускались.

В изолированном архиве `93c6555` оба новых теста собраны напрямую из исходников
после `touch`: сборка каждого exit 0, выполнение каждого exit 1. Локальные логи:
`/tmp/d2k-baseline-runtime-final.log`, `/tmp/d2k-baseline-probe-final.log`;
зелёные полные наборы — `/tmp/d2k-{core,detect,datapath}-check-final.log`.
Это временные диагностические файлы машины, не долговременные артефакты git.

Это локальные и cross-свидетельства. Не проверены реальные Linux raw sockets,
NFQUEUE/NAT, маршрутизатор, wall-clock точность задержек, рабочие браузеры и
конечное приложение. Равенство доказано при одинаковых payload, адресах,
seq/ack, options и входной энтропии. Новый поток естественно имеет свои
адреса/порты/seq/TS/random; сохранение старых абсолютных заголовков вместо
контекста нового потока не требуется и не реализовано.

Оставшиеся границы: owned-decoy/overlap до 2048; SYN-data не выражается Plan;
безымянный OOB не стал поддержанным именованным TLS-планом. Ошибки таких
контекстов не являются ответами коробки. QUIC/STUN/voice не сливались с TCP.

## Следующий пункт

Владелец выполняет ограниченный полевой прогон семейства C: свойство →
`plan-680fbe00` → verifier → приложение, отдельно от факта APPLIED. Проверить
rutracker.org и другую цель семейства, затем прежние рабочие гипотезы; сохранить
ревизию/контекст/план/пакетные свидетельства. Автоматического разрешения менять
роутер этот handoff не даёт. Если останется отказ, разбирать контекст
SYN-ACK/TS, реальную клиентскую форму и маршрутные ограничения общего
исполнителя, не возвращать независимый raw-сборщик обхода.
