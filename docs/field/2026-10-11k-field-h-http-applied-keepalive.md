## Диагноз

Разрыва «план ≠ провод» нет: план на проводе, приманка байт-в-байт как у замера,
главная страница берётся. Дефект уже: **приманка срывает инъекцию только на
ПЕРВОМ запросе коннекта; на последующих keep-alive подзапросах портал
по-прежнему вставляет 302**, хотя D2K приманку шлёт. Этот DPI переинспектирует
каждый запрос в keep-alive (не только первый), а overlap-приманка mid-stream его
не обманывает. Отсюда частичный рендер: главный HTML есть, часть подресурсов
уводится на портал.

Это согласуется с zapret: приманка/десинхром должны применяться к КАЖДОМУ
HTTP-запросу, либо запрос должен идти новым коннектом (Connection: close),
либо для mid-stream запроса нужен более сильный десинхром (разрез Host,
smена позиции, fakedsplit), чем для первого.

## Следующий пункт (Astra)

Приманка должна защищать КАЖДЫЙ keep-alive запрос, не только первый. Варианты:
(а) per-request переприменение с корректным mid-stream overlap/позицией;
(б) принудительный Connection: close / split каждого запроса;
(в) для подзапроса использовать `fake-badsum` с разрезом Host (method+2), а не
только `whole`. Падающий тест: на одном коннекте два последовательных запроса —
второй тоже не получает портальный 302. Эффективность на живом DPI подтвердить
полем (pcap: нет 302 ни на одном запросе коннекта).
