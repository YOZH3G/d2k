```

10:41:49 по rutracker.org (TCP) ПОДТВЕРЖДЕНО собственным зондом: plan-680fbe00 (путь: свой план)
```

Тот же след у fost.club (10:31:17 → 10:41:29). Коробка не ответила SYN-ACK на
зонд разреза. Код (`core/sched.c:9004-9029`) трактует любой `D2K_V_FLAKY`
(«измерению верить нельзя», сюда же `detect/raw.c:1029` «SYN-ACK не пришёл»)
как «результат неубедителен» → `cooldown_record(…,2)` → `SCHED_INCOMPLETE_BACKOFF_MS`
= 10 мин. При повторе план нашёлся за 3–4 с. Штраф за неуверенность в 10 мин
получили 6 целей (rutracker.org, fost.club, mask.icloud.com, waa-pa.clients6.google.com,
два имени *.ru).

Открытый вопрос классификации (решение — за кодом, не за полем): отсутствие
SYN-ACK на зонд при живом прямом трафике браузера — это ошибка замера или
измеренное свойство коробки (транспортный срез, как у flibusta #19)? Сегодня
оно равно «ничего не знаем, ждём 10 мин».

Сопутствующее: «ограниченная очередь заполнена» — 42 раза за прогон при лимите
3 одновременных замера; QUIC-перебор по ~50 опытов на цель занимает слоты.

## Метрика прогона (задача #5) не печатается

В журнале нет ни одной итоговой строки «доля без перебора / зондов / время».
`core/sched.c:993` считает `r.probes` для конкретного прогона, но сводки по
прогону d2kc не выдаёт. Таблицы выше собраны вручную grep'ом. Пока сводки нет,
прогресс «замер вместо перебора» невидим ни владельцу, ни ревью.

   10-минутный штраф вместо вывода. Нужна классификация, а не таймер.
2. QUIC: 0 измеренных свойств, сразу перебор, 13/15 провалов по 50 опытов.
   Либо путь замера, либо измеримое решение «обход QUIC не окупается → отдавать
   браузер на TCP за секунду» (решение за дизайном, поле даёт только цифры).
3. Печать сводки прогона в журнал: по каждой цели путь (свойство / свой план /
   перебор / провал / прямой) и время до ПОДТВЕРЖДЕНО, чтобы каждый прогон
   давал эту таблицу сам.
4. fast-torrent (портал на keep-alive) и mailsuite (объёмный обрыв) — как в
   `2026-10-11k`.
