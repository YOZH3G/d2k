# Native IPv6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement task-by-task. Track completion with the checkboxes below.

**Goal:** Автоматический подбор и исполнение TLS 1.2/1.3 и QUIC по IPv6 на роутере, сохранение IPv4, поле на телефоне и опубликованный релиз.
**Architecture:** Расширить адресные и пакетные контракты существующего C-движка. Сохранить дерево поиска; семейство проходит через наблюдение, опыт, подтверждение и каталог без подмены.
**Tech Stack:** C99, Linux NFQUEUE/raw sockets, ip6tables, существующие Makefile и Zig-сборки.
**Spec:** `docs/superpowers/specs/2026-09-28-ipv6-design.md` (согласована владельцем).

## Global Constraints

- Главный контракт — `D2K_SPEC.md`; никакого второго измерителя и начальных списков.
- TLS 1.2, TLS 1.3 и QUIC проверяются каждый своим протоколом.
- Отключение IPv6, подавление AAAA и перевод QUIC на TCP не являются решением.
- Старые IPv4-записи сохраняются как IPv4, не становятся универсальными.
- Все продуктовые компоненты на роутере остаются C.
- Не трогать пользовательские `.impeccable/` и `PRODUCT.md`, не публиковать секреты.
- Рабочее дерево уже изолировано: `d2k-telegram-tunnel`, ветка `feat/telegram-tunnel`.
- На роутер выкатывать только согласованный комплект с резервной копией и откатом.

## Review Focus

1. IPv6-адреса с одинаковыми младшими 32 битами не объединяют клиентов/опыты — задача 1.
2. Обрыв обновления между бинарниками не разрешает чужой формат control — задачи 2 и 7.
3. IPv6 extensions/фрагменты и маленький PMTU не повреждают исходный трафик — задачи 3 и 7.
4. Успех IPv4 не останавливает поиск IPv6 того же домена — задача 5.
5. Пересоздание NDM-правил и падение процесса не кладут интернет — задача 6.

## 1. Адреса и ключи потоков

**Files:** новые `datapath/include/d2k_addr.h`, `datapath/addr.c`, `datapath/test_addr.c`; `datapath/include/d2k_track.h`, `datapath/track.c`, `datapath/test_track.c`; Makefile потребителей.
**Interface:** `d2k_addr { uint8_t family; uint8_t bytes[16]; }`, family=4/6, сетевые байты; IPv4 в первых четырёх байтах, остаток нулевой. `int d2k_addr_parse(const char *, d2k_addr *)`, `size_t d2k_addr_text(const d2k_addr *, char *, size_t)`, `int d2k_addr_equal(const d2k_addr *, const d2k_addr *)`. Parse: 0=успех, -1=ошибка; text: 0=ошибка. Никакого DNS внутри parse.
**Key interface:** добавить `int d2k_key_make_addr(d2k_key *, uint8_t proto, const d2k_addr *src, const d2k_addr *dst, const uint8_t *sport_be, const uint8_t *dport_be)`; существующий IPv4-конструктор оставить адаптером. Смешанное семейство отвергать (-1); 0/1 сохраняют направление.

- [ ] RED: `test_addr` проверяет roundtrip `2001:db8::1`, `192.0.2.1`, отказ мусора и короткого буфера; `test_track` — разные верхние 96 бит, обратное направление и разные семейства дают правильные ключи. Запустить, зафиксировать ожидаемый отказ.
- [ ] Реализовать адресный модуль и полный ключ; обновить сравнение, хеш и потребителей без усечения. Не хранить строку адреса в каждом пакете.
- [ ] GREEN: `make -C datapath check`, затем sanitizer-цель из Makefile. Коммит только файлов задачи.

## 2. События и изоляция планов

**Files:** `datapath/include/d2k_ctl.h`, `d2k_ctlsrv.h`, `d2k_plans.h`, `datapath/ctlsrv.c`, `plans.c`, `ctlprobe.c`; `core/include/d2k_link.h`, `core/link.c`; `internal/control/control.go`; соответствующие `test_ctl.c`, `test_plans.c`, `test_link.c` и Go-тесты.
**Interface:** control version 4; ключ на проводе — family(1), low address(16), high address(16), low/high port(2+2), proto(1), всего 38 байт. Кодировать полями, не sizeof(struct). Family обязательно в name/addr-привязках и точном probe-контексте. Старые IPv4 API при необходимости остаются thin wrappers с family=4; в новой вертикали использовать полный адресный интерфейс.

- [ ] RED: roundtrip ключа IPv6 через реальный ctlprobe/link; v3/v4 отвергаются при handshake; удаление IPv6 trial не удаляет IPv4 либо чужой порт/trial того же имени; усечённые сообщения не меняют таблицу.
- [ ] Обновить producer и всех consumer, длины, границы кадров, события snapshot/HELLO/SUSPECT/APPLIED/EXCHANGE; семейство учитывать при установке, выборе и удалении плана.
- [ ] GREEN: `make -C datapath check`, `make -C core check`, `go test ./internal/control/...`; коммит.

## 3. Пакетный путь IPv6

**Files:** новые `datapath/include/d2k_ip.h`, `datapath/ip.c`, `datapath/test_ip.c`; `session.c`, `hold.c`, `udp_hold.c`, `capture.c`, `wire.c`, `wire_udp.c`, `raw.c`, `d2kd.c` и их заголовки/тесты.
**Interface:** `d2k_ip_view` содержит `d2k_addr src,dst`, transport, hop_limit, l4_offset, packet_len, fragmented. `int d2k_ip_parse(const uint8_t *, size_t, d2k_ip_view *)`: 0=валидный разбор, -1=отказ; выходы проверяются до доступа. Разбор не выделяет память. Ограничить цепочку расширений 16 заголовками, jumbo не поддерживать и пропускать без модификаций.
**Wire:** `d2k_conn` несёт семейство и полные адреса; существующие `d2k_wire_build`/`d2k_wire_build_udp` выбирают заголовок по семье. Сырые IPv6 отправки используют отдельный AF_INET6 fd и ту же защиту от рекурсии/учёт результата, что IPv4.

- [ ] RED: IPv6 TCP/UDP с независимыми эталонными checksum; truncated/extensions/fragment inputs; TCP hello через два сегмента; QUIC CRYPTO через несколько Initial; маленький выходной буфер. Корректная нагрузка не усечена; некорректный пакет ACCEPT без ложного успеха.
- [ ] Подключить общий IP-разбор в session/hold/capture, IPv6 сборку и отправку, Hop Limit и MTU. Не применять IPv4 NAT-переписывание к IPv6. Проверить netmap/conntrack фактического роутера до поля, а не предполагать отсутствие трансляции.
- [ ] IPv4-only воздействия помечать неприменимыми; переносимые фрагментные воздействия реализовать с IPv6 Fragment header и отдельными wire-тестами. Не удалять целое семейство гипотез ради зелёного теста.
- [ ] GREEN: `make -C datapath check` плюс Linux-стенд IPv6 отправки/обратного ответа и MTU; сравнить IPv4 golden vectors; коммит.

## 4. Измерение и подтверждение в IPv6

**Files:** `core/meas.c`, `props.c`, `quicprobe.c`, `quicconn.c`, `tls12.c`, `tls13.c`, `verify.c`, `volume.c`, `ipfrag.c` и соответствующие заголовки; `detect/raw.c`, `detect/props.c`, bridge-потребители; существующие socket/wire-тесты.
**Interface:** текстовые IP-входы принимают literal IPv6 без изменения смысла портов; локальный адрес опыта возвращается как `d2k_addr`, не `uint8_t[4]`. Добавить `int d2k_qc_local_addr(const d2k_qc *, d2k_addr *, uint16_t *)`; IPv4 accessor оставить только для старых IPv4 callers. Контрольные цели разрешаются в семье исследуемого потока.

- [ ] RED: реальные loopback-серверы `::1` отдельно для TLS 1.2, TLS 1.3, QUIC; exact local tuple; отказ IPv6 connect не создаёт IPv4 fd/успех. Нет IPv6-контроля — недостоверный замер, не доказанный блок.
- [ ] Перенести socket/address/getsockname/TTL ancillary paths на семейство; пробные планы получают exact IPv6 tuple и правильную mark. Алгоритм вопросов не перестраивать.
- [ ] Сверить применимость каждого сырого воздействия с донором и текущим wire; неподдержанное не выдавать за проверенное отрицательно.
- [ ] GREEN: `make -C core check`, `make -C detect check`, Linux IPv6 socket/mark стенд; коммит.

## 5. Автопоиск, каталог и панель

**Interface:** `family`=4/6 в контексте задачи, подтверждённой привязке и live/API. Старые записи без family читаются как 4, не wildcard; новые записи всегда сохраняют family. Бюджеты и дедупликация учитывают семью, глобальный бюджет не удваивается.
